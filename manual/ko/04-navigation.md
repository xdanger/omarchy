# 탐색

Omarchy의 모든 것은 키보드로 이루어진다 — _모든 것이다!_ 시스템이 처음 시작되면, 말 그대로 마우스만으로는 아무것도 할 수 없다. 하지만 `Super + Space`를 누르면 Omarchy 메뉴가 나타나고, 여기서 거의 모든 것을 할 수 있다.

하지만 Omarchy 메뉴는 대부분의 시간에 시스템을 조작하는 주된 방법이 되도록 의도된 것조차 아니다. 우리는 그보다 더 빨라질 수 있다! 가장 중요한 애플리케이션들은 모두 개별 단축키에 직접 연결되어 있다. `Super + Return`으로 터미널을 시작하고 `Super + Shift + Return`으로 브라우저를 시작한다. 하나씩 차례로 실행해 보면 Hyprland 타일링의 마법이 작동하는 모습을 볼 수 있을 것이다:

 ![navigation-browser-terminal](images/navigation-browser-terminal.webp)

그런 다음 `Super + J`를 누르면 나란히 있는 대신 위아래로 쌓을 수 있다:

 ![navigation-stacked](images/navigation-stacked.webp)

`Super + J`를 다시 누르면 나란히 있는 위치로 돌아간다. 그런 다음 브라우저에 있는 동안 `Super + Shift + Arrow Right`를 눌러 창들을 바꿔 보라.

이제 `Super + Shift + T`를 눌러 Activity 모니터를 시작해 보라. 그것은 떠 있는 창으로 나타날 것이다. `Super + T`를 사용해 타일링할 수 있다(그리고 다시 누르면 다시 떠 있게 만들 수 있다). 이제 `Super + Shift + F`를 눌러 파일 관리자를 열어 보라. 깔끔한 4분할 구성이 될 것이다:

 ![navigation-fourway-tiling](images/navigation-fourway-tiling.webp)

`Super + Arrow`로 활성화하려는 창 사이를 탐색한다. 그러면 초점이 전환되고 커서가 새 애플리케이션의 중앙으로 이동한다. 화면 가장자리에서는 그쪽에 있는 모니터로 이어진다.

`Super + Shift + 2`를 누르면 현재 초점이 맞춰진 애플리케이션이 두 번째 작업 공간으로 이동한다. `Super + Shift + 1`은 그것을 다시 되돌린다. (그리고 `Super + Shift + Alt + 2`는 현재 초점이 맞춰진 애플리케이션을 두 번째 작업 공간으로 이동시키지만 그곳으로 전환하지는 않는다).

모니터가 두 대 이상이면, 각 모니터마다 자체적인 1부터 10까지의 작업 공간이 있다. `Super + 2`는 현재 있는 모니터의 두 번째 작업 공간으로 이동하고, 각 모니터의 상단 바에는 자체 작업 공간들과 현재 표시 중인 작업 공간이 표시된다. `Super + Tab`은 현재 있는 모니터의 작업 공간들을 순환한다. `Super + Shift + Ctrl + Arrows`는 현재 있는 창을 그 방향에 있는 모니터로, 그곳에서 표시 중인 작업 공간으로 이동시키고, `Super + Shift + Alt + Arrows`는 현재 있는 작업 공간을 그 방향에 있는 모니터로 이동시키며, 그곳에서 비어 있으면 같은 번호를 차지한다. 모니터는 분리해도 작업 공간을 유지한다: 그것들은 다른 화면의 작업 공간에 합쳐져 이미 있는 것들 뒤에 번호가 매겨지고, 모니터가 돌아오면 옛 번호 아래로 돌아간다.

`Super`를 누른 채 마우스로 창을 클릭하면, 그 창이 자리한 위치를 재배열할 수 있다. `Super`를 누른 채 마우스의 오른쪽 버튼을 사용하면, 창의 크기를 자유롭게 조정할 수 있다.

창은 `Super + W` 또는 `Super + Q`로 닫는다(그리고 모든 창은 `Ctrl + Alt + Delete`로 닫는다).

`Super + F`로 전체 화면으로 전환하거나, `Super + Alt + F`로 상단 바를 유지한 채 너비만 가득 채우거나, `Super + Ctrl + F`로 창 안에서의 전체 화면으로 전환할 수도 있다(YouTube에 좋다!).

### Dwindle vs 스크롤 레이아웃

Omarchy의 기본 레이아웃은 dwindle이라고 불린다. 그것은 단일 작업 공간에 여는 모든 창을, 크기를 줄여야 하더라도, 항상 보이게 유지한다.

 ![navigation-dwindle-layout](images/navigation-dwindle-layout.webp)

하지만 창들이 표시 영역의 보이는 가장자리를 넘어 나란히 줄지어 있는 스크롤 레이아웃으로 작업 공간을 전환하도록 선택할 수도 있다. `Super + L`을 통해 단일 작업 공간을 이 레이아웃으로 전환한다.

`Super + L`을 다시 누르면 작업 공간이 플로팅으로 전환되며, 여기서는 창들이 자유롭게 겹치고 직접 배치하게 되고, 세 번 누르면 dwindle로 돌아간다. `Super + Alt + L`은 반대 방향으로 그것들을 순환한다. 어쨌든 떠 있는 창 — `Super + T`로 분리해 낸 창이나, 항상 떠 있는 상태로 열리는 앱 — 은 작업 공간이 다시 타일링으로 돌아가도 계속 떠 있다. 상단 바는 현재 있는 작업 공간을 그 레이아웃으로 표시한다: dwindle은 정사각형, 스크롤은 원, 플로팅은 삼각형이다. 그 표시를 클릭해도 레이아웃이 순환한다.

 ![navigation-scrolling-layout](images/navigation-scrolling-layout.webp)

선택은 작업 공간별로 이루어지며, 유지된다. 따라서 작업 공간 1은 탐색용으로 dwindle에 두고 작업 공간 2는 코드용으로 스크롤에 둘 수 있으며, 재시작 후에도 그런 상태로 돌아올 것이다.

스크롤 레이아웃을 기본값으로 사용하고 싶다면, `~/.config/hypr/looknfeel.lua`에서 설정할 수 있다:

```lua
hl.config({
  general = {
    layout = "scrolling",
  },
})
```

### 플로팅 작업 공간

플로팅 작업 공간은 전통적인 데스크톱처럼 작동한다: 창들이 겹치고, 직접 이동하고 크기를 조정한다. 각 창은 테마 색상의 타이틀바를 가지며, 최소화, 최대화, 닫기 버튼이 있다. `Super + M`도 초점이 맞춰진 창을 최소화한다. 최소화된 창은 독에서 기다린다; 그 앱을 클릭하면 다시 돌아온다. 창을 클릭하면 앞으로 가져온다. 어느 가장자리나 모서리에서든 크기를 조정한다. 타이틀바를 두 번 클릭하면 상단 바를 볼 수 있게 유지하면서 창을 최대화하고, 다시 두 번 클릭하면 옛 크기로 돌아온다. Chrome 및 기타 Chromium 기반 브라우저, Disks와 Document Viewer는 타이틀바를 건너뛰고 대신 자체 헤더를 사용한다; `Super + Alt + F`가 그것들을 최대화하고, `Super + M`이 그것들을 최소화한다.

플로팅 작업 공간에는 고정된 앱, 실행 중인 모든 것이 있는 독도 표시되며, 앱 버튼 뒤에는 모든 앱의 격자가 있는데, 이는 `Super + Alt + Space`와 Omarchy 메뉴의 _Apps_로도 열 수 있다. 격자에서 앱을 마우스 오른쪽 버튼으로 클릭하거나 `Delete`를 누르면 제거할 수 있다. 앱을 클릭하면 열거나, 그 창을 앞으로 가져온다; 다시 클릭하면 그 창들을 순환한다. Files는 현재 있는 작업 공간에서만 창을 되돌려오고 그렇지 않으면 새 창을 열며, Terminal과 Agent는 항상 또 하나를 시작하지만, 최소화된 창이 먼저 돌아온다. 가운데 버튼 클릭은 새 창을 연다. 독을 따라 아이콘을 드래그하면 이동한다; 실행 중인 앱을 다른 앱들 사이로 드래그하면 그곳에 유지된다. 마우스 오른쪽 버튼으로 클릭하면 앱을 독에 유지하거나, 독에서 빼거나, 종료할 수 있다. 전체 화면 창이 있으면 독이 비켜난다. 앱 버튼을 마우스 오른쪽 버튼으로 클릭하면 독을 다른 가장자리로 이동시키거나 포인터가 그 가장자리에 닿을 때까지 숨기게 할 수 있다. 위치는 _Appearance > Dock > Dock Position_ 아래에도 있으며, `omarchy dock position left`와 `omarchy dock autohide on`은 터미널에서 둘 다 설정한다. 독에 유지하는 앱은 실행 중이 아닐 때 흐리게 표시된다.

새 작업 공간과, `Super + L`로 자체 레이아웃을 부여하지 않은 모든 작업 공간은 기본 레이아웃을 사용한다. 기본값을 변경하면 창이 없는 모든 작업 공간이 그것으로 재설정되는 반면, 창이 있는 작업 공간은 갖고 있는 레이아웃을 유지한다. 독으로 최소화된 창은 여전히 떠난 작업 공간에 있는 창으로 간주된다. _Appearance > Workspace Layout_ 아래에서 선택하라: Tiling, Scrolling, 또는 Floating. `omarchy-hyprland-workspace-layout-default scrolling`은 터미널에서 설정한다.

### 창 그룹화

창은 `Super + G`를 사용해 그룹화할 수 있다. 그룹에 들어가면, 그것이 활성화된 동안 시작하는 모든 창은 그 그룹에 속하게 된다. `Super + Ctrl + Arrow Left/Right`를 사용하거나 `Super + Alt + 1/2/3/4`를 사용해 순서대로 그룹화된 창으로 직접 이동하여, 그룹화된 창들 사이를 이동할 수 있다.

`Super + Alt + G`로 창을 그룹화에서 빼내거나, `Super + G`를 다시 눌러 전체 그룹을 해체할 수 있다. 마지막으로, `Super + Alt + Arrows`로 그룹 밖에 있는 창을 그룹 안으로 이동시킬 수 있다.

### 창 팝아웃하기

`Super + O`로 창을 그 작업 공간 할당에서 분리해 낼 수 있다. 그러면 어느 작업 공간으로 가든 따라다니는 떠 있는 창으로 고정된다. 동영상 플레이어 같은 것에 아주 좋다.

 ![navigation-popped-window](images/navigation-popped-window.webp)

### 스크래치패드 작업 공간

현재 있는 작업 공간 위에 겹쳐지는 특별한 전체 크기 스크래치패드 작업 공간이 있다. `Super + S`를 사용해 그 위에 있는 것에 접근하고, `Super + Alt + S`를 사용해 그곳에 창을 배치한다.

현재 작업 공간을 떠나지 않고 빠르게 상호작용하고 싶은 컨트롤이나 터미널에 잘 작동한다.

### Quake 콘솔

마지막으로, 현재 있는 작업 공간 위로 내려오는 절반 높이의 Quake 콘솔이 있다. `Super + Grave`로 토글하고, `Super + Shift + Grave`를 사용해 그곳에 창을 배치한다.

기본 에이전트가 바로 사용할 수 있는 상태로 열린다. 콘솔에 단일 창이 있는 동안은, 화면 전체에 걸쳐 나타나기보다는 중앙에 배치된 패널로 내려온다. 두 번째 앱을 그곳에 두면 전체 너비로 돌아가므로, 두 앱이 나란히 자리할 공간이 생긴다.

스크래치패드나 콘솔에서 창을 옮기려면, `Super + Shift + 1` 같은 것으로 다른 작업 공간에 직접 보내라.

### 익숙해지려면 시간이 좀 걸린다!

이런 식으로 데스크톱을 탐색하는 데 익숙해지려면 시간이 조금 걸리지만, 일단 익숙해지면 전통적인 마우스 중심 데스크톱 경험으로 돌아가기 어려울 것이다!
