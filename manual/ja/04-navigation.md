# ナビゲーション

Omarchy のすべてはキーボードで操作する —— _すべてだ！_ システムが初めて起動したときは、マウスだけでは文字通り何もできない。しかし `Super + Space` を押せば Omarchy Menu が表示され、ここからほぼ何でもできる。

しかし Omarchy メニューは、そもそも普段システムを操作する主な方法として意図されたものでさえない。もっと速くできる！最も重要なアプリケーションはすべて、個別のホットキーに直接割り当てられている。ターミナルは `Super + Return`、ブラウザは `Super + Shift + Return` で起動する。続けて両方試してみれば、Hyprland のタイリングの魔法が実際に動くのがわかるだろう：

 ![navigation-browser-terminal](images/navigation-browser-terminal.webp)

次に `Super + J` を押すと、左右に並べるのではなく、上下に重ねて積み重ねることができる：

 ![navigation-stacked](images/navigation-stacked.webp)

`Super + J` をもう一度押すと、左右に並んだ位置に戻る。次に、ブラウザにいるときに `Super + Shift + Arrow Right` を試して、ウィンドウを入れ替えてみよう。

次に `Super + Shift + T` を試して Activity モニターを起動しよう。それはフローティングウィンドウとして表示される。`Super + T` を使ってタイリングでき（もう一度押すと再びフローティングになる）。次に `Super + Shift + F` を押してファイルマネージャーを開こう。きれいな4分割のレイアウトになる：

 ![navigation-fourway-tiling](images/navigation-fourway-tiling.webp)

アクティブにしたいウィンドウ間の移動は `Super + Arrow` で行う。これでフォーカスが切り替わり、カーソルが新しいアプリケーションの中央に移動する。画面の端では、その方向にあるモニターへそのまま移動する。

`Super + Shift + 2` を押すと、現在フォーカスしているアプリケーションが2番目のワークスペースに移動する。`Super + Shift + 1` で戻る。（そして `Super + Shift + Alt + 2` では、現在フォーカスしているアプリケーションを、そちらに切り替えることなく2番目のワークスペースに移動できる）。

モニターが複数ある場合、各モニターはそれぞれ独自の1から10までのワークスペースを持つ。`Super + 2` は現在のモニターの2番目のワークスペースに移動し、各モニターのトップバーには、そのモニター独自のワークスペースと現在表示しているものが表示される。`Super + Tab` は現在のモニター上のワークスペースを順に切り替える。`Super + Shift + Ctrl + Arrows` は現在のウィンドウをその方向のモニターへ、そのモニターが表示しているワークスペース上に移動し、`Super + Shift + Alt + Arrows` は現在のワークスペースをその方向のモニターへ移動し、空いていれば同じ番号になる。モニターを取り外しても、そのワークスペースは保持される：別の画面のワークスペースに加わり、すでにあるものの後ろに番号が付けられ、モニターが戻ると元の番号に戻る。

`Super` を押しながらマウスでウィンドウをクリックすれば、その配置を変えることができる。`Super` を押しながらマウスの右ボタンを使えば、ウィンドウを自由にリサイズできる。

ウィンドウは `Super + W` または `Super + Q` で閉じる（すべてのウィンドウは `Ctrl + Alt + Delete` で閉じる）。

`Super + F` でフルスクリーンにもできるし、`Super + Alt + F` で（トップバーを残したまま）全幅だけにすることも、`Super + Ctrl + F` でウィンドウ内のフルスクリーンにすることもできる（YouTube に最適だ！）。

### Dwindle vs scrolling レイアウト

Omarchy のデフォルトレイアウトは dwindle と呼ばれる。1つのワークスペースで開いたすべてのウィンドウを、縮小してでも常にすべて表示し続ける。

 ![navigation-dwindle-layout](images/navigation-dwindle-layout.webp)

しかし、ウィンドウを表示画面の見える端を超えて左右に並べる scrolling レイアウトにワークスペースを変えることも選べる。1つのワークスペースをこのレイアウトにするには `Super + L` を使う。

`Super + L` をもう一度押すとワークスペースがフローティングになり、ウィンドウが自由に重なり、自分で配置できるようになり、3回目で dwindle に戻る。`Super + Alt + L` では逆の順序で切り替わる。もともとフローティングしているウィンドウ —— `Super + T` で切り離したものや、常にフローティングで開くアプリ —— は、ワークスペースがタイリングに戻ってもフローティングのままである。トップバーは現在のワークスペースに、そのレイアウトを示すマークを表示する：dwindle は四角、scrolling は円、floating は三角形だ。そのマークをクリックしてもレイアウトが切り替わる。

 ![navigation-scrolling-layout](images/navigation-scrolling-layout.webp)

この選択はワークスペースごとで、保持される。だからワークスペース1はブラウジング用に dwindle、ワークスペース2はコード用に scrolling にしておけば、再起動後もその状態に戻る。

scrolling レイアウトをデフォルトとして使いたい場合は、`~/.config/hypr/looknfeel.lua` で設定できる：

```lua
hl.config({
  general = {
    layout = "scrolling",
  },
})
```

### フローティングワークスペース

フローティングワークスペースは従来のデスクトップのように動作する：ウィンドウが重なり、自分で移動してサイズを決める。各ウィンドウにはテーマの色のタイトルバーが付き、最小化、最大化、閉じるボタンがある。`Super + M` でもフォーカスしたウィンドウを最小化できる。最小化したウィンドウは dock で待機する；そのアプリをクリックすれば戻る。ウィンドウをクリックすれば前面に来る。どの端や角からでもリサイズできる。タイトルバーをダブルクリックすると、トップバーを表示したままウィンドウが最大化され、もう一度ダブルクリックすると元のサイズに戻る。Chrome やその他の Chromium ベースのブラウザ、Disks、Document Viewer はタイトルバーを省略し、代わりに独自のヘッダーを使う；それらは `Super + Alt + F` で最大化し、`Super + M` で最小化する。

フローティングワークスペースには dock も表示され、ピン留めしたアプリ、実行中のすべてのもの、そして apps ボタンの奥にあるすべてのアプリのグリッドがある。このグリッドは `Super + Alt + Space` や Omarchy メニューの _Apps_ でも開ける。グリッド上のアプリを右クリックするか、`Delete` を押すと、そのアプリをアンインストールできる。アプリをクリックすると、それを開くか、そのウィンドウを前面に持ってくる；もう一度クリックすると、そのウィンドウを順に切り替える。Files は現在のワークスペースからウィンドウを持ち戻すだけで、それ以外は新しいウィンドウを開き、Terminal と Agent は常にもう1つ起動するが、最小化したウィンドウが先に戻る。中クリックすると新しいウィンドウが開く。アイコンを dock に沿ってドラッグすると移動できる；実行中のアプリを他のアプリの間にドラッグすれば、そこに留まる。右クリックすると、アプリを dock に保持したり、dock から外したり、終了したりできる。dock はフルスクリーンウィンドウの邪魔にならないように退く。apps ボタンを右クリックすると、dock を別の端に移動したり、ポインターがその端に到達するまで隠したりできる。その位置は _Appearance > Dock > Dock Position_ にもあり、`omarchy dock position left` と `omarchy dock autohide on` でターミナルから両方を設定できる。dock に保持したアプリは、実行されていない間は薄く表示される。

新しいワークスペースと、`Super + L` で独自のレイアウトを与えていないワークスペースは、デフォルトレイアウトを使う。デフォルトを変更すると、ウィンドウのないすべてのワークスペースはそれにリセットされるが、ウィンドウがあるワークスペースは現在のレイアウトを保持する。dock に最小化したウィンドウも、それが離れたワークスペース上のウィンドウとして依然として数えられる。_Appearance > Workspace Layout_ で選ぶ：Tiling、Scrolling、または Floating。`omarchy-hyprland-workspace-layout-default scrolling` でターミナルから設定する。

### ウィンドウのグループ化

ウィンドウは `Super + G` を使ってグループ化できる。グループに入ると、それがアクティブな間に起動したすべてのウィンドウがそのグループに属する。グループ化したウィンドウ間は `Super + Ctrl + Arrow Left/Right` で移動でき、`Super + Alt + 1/2/3/4` で順番にグループ化したウィンドウへ直接移動できる。

ウィンドウをグループ化から外すには `Super + Alt + G` を使い、グループ全体を解体するには `Super + G` をもう一度押す。最後に、グループの外にあるウィンドウを `Super + Alt + Arrows` でグループ内へ移動できる。

### ウィンドウのポップアウト

`Super + O` でウィンドウをそのワークスペース割り当てから切り離すことができる。それにより、どのワークスペースに移動してもついてくるフローティングウィンドウとしてピン留めされる。動画プレイヤーなどに最適だ。

 ![navigation-popped-window](images/navigation-popped-window.webp)

### Scratchpad ワークスペース

現在のワークスペースの上に重なる、フルサイズの特別な scratchpad ワークスペースがある。そこにあるものには `Super + S` でアクセスし、ウィンドウをそこに配置するには `Super + Alt + S` を使う。

現在のワークスペースを離れることなく、素早く操作したいコントロールやターミナルに適している。

### Quake コンソール

最後に、現在のワークスペースの上にドロップダウンする、半分の高さの Quake コンソールがある。`Super + Grave` で切り替え、ウィンドウをそこに配置するには `Super + Shift + Grave` を使う。

開くと、デフォルトの agent がすぐに使える状態になっている。コンソールにウィンドウが1つだけの間は、画面いっぱいに広がるのではなく、中央のパネルとしてドロップダウンする。そこに2つ目のアプリを置くと全幅に戻り、2つが左右に並ぶ余地ができる。

scratchpad またはコンソールからウィンドウを移動するには、`Super + Shift + 1` のようにして別のワークスペースへ直接送る。

### 慣れるまで少し時間がかかる！

このようにデスクトップをナビゲートすることに慣れるまで少し時間がかかるが、一度慣れれば、従来のマウス中心のデスクトップ体験に戻るのは難しくなるだろう！
